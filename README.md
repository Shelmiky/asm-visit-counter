# Счётчик запусков

Итоговый проект по системному программированию. Linux x86-64, NASM, прямые системные вызовы без стандартной библиотеки.

## Сборка и запуск

Нужны NASM и GNU binutils. На Ubuntu/Debian: `sudo apt install nasm binutils make python3`.

```sh
nasm -f elf64 -Werror counter.asm -o counter.o
ld -o program counter.o
./program
./program
./program
cat count.txt
```

В каталоге без `count.txt` результат:

```text
Visits: 1
Visits: 2
Visits: 3
3
```

Можно использовать `make`, `make test` и `make clean`. `make clean` удаляет только результаты сборки, не счётчик. На Windows нужен Linux: WSL либо контейнер Docker.

## Как работает

1. `open` открывает `count.txt` в текущем каталоге для чтения и записи, создавая его при отсутствии с правами 0644 с учётом umask.
2. `flock` ставит исключительную блокировку для согласованного обновления при нескольких запусках этой программы.
3. `read` читает файл до EOF. При чтении используются фактически полученные длины из `rax`; переполнение буфера исключено. Пустой файл считается нулём.
4. Десятичные цифры преобразуются в 64-битное беззнаковое число; проверяются формат и переполнение. Число увеличивается на один и преобразуется обратно в строку.
5. `lseek` возвращает позицию на начало, `write` записывает число и LF, `ftruncate` убирает оставшийся хвост старой строки, `fsync` проверяет сохранение, `close` закрывает дескриптор и снимает блокировку.
6. В stdout выводится `Visits: N`. Успешное завершение возвращает 0; ошибка — сообщение в stderr и код 1.

Непустой файл должен содержать 1–20 цифр, допускается один завершающий LF. Пробелы, знак, CRLF и другой текст отклоняются. Максимальный результат — `18446744073709551615`; попытка увеличить его завершается ошибкой. Некорректные исходные данные не перезаписываются. Дескриптор и длины хранятся не в `rcx`/`r11`, которые изменяет `syscall`. Частичные записи и EINTR при чтении/записи обрабатываются.

## Проверка

```sh
make test
```

`check.py` запускает настоящий собранный ELF в отдельном временном каталоге. Проверяет создание файла, последовательные запуски, переходы 9→10 и 99→100, ведущие нули, большие числа, границы uint64, ошибочные данные, ошибку открытия, сбой вывода и 40 параллельных запусков. При запуске тестов от root дополнительно проверяется файл без права записи от непривилегированного пользователя. Рабочий `count.txt` пользователя не затрагивается.

`test-results.txt` содержит фактический вывод успешного запуска проверки: 27 проверок в Linux x86-64 (Docker, NASM 2.16.03, GNU ld 2.45.1). Скриншоты отчёта проверки подготавливаются для сдачи отдельно; отчёт не выдаётся за изображение терминала.

Соглашение о регистрах системных вызовов: [Linux man-pages, syscall(2)](https://man7.org/linux/man-pages/man2/syscall.2.html).

## Ограничения

Файл обновляется на месте: аварийное выключение во время записи не гарантирует сохранение предыдущего значения. Блокировка работает для экземпляров этой программы, но не запрещает сторонней программе менять файл без блокировки. Счётчик сохраняется до вывода в stdout; ошибка вывода не отменяет уже сохранённое увеличение.
